# 项目架构说明

## 总体分层

项目以 Unity MonoBehaviour 为运行入口，核心代码按职责拆分为五层：

- `Framework`：通用基础设施，包括单例、资源加载、AssetBundle、对象池、事件中心、UI、音频、场景和时间线管理。
- `Combat`：战斗系统，包括战斗形态、连招数据、武器攻击逻辑、投射物和技能上下文。
- `Character`：角色系统，包括玩家、敌人、NPC、角色模型、数值数据和状态机。
- `AI`：行为树系统，提供 Selector、Sequence、Decorator、Filter 等节点，并由敌人模块组合使用。
- `UI`：所有面板脚本，包括 HUD、背包、对话、商店、交互提示和战斗提示。

## 运行关系

`Character` 是玩法主体，玩家和敌人都通过状态机处理动作切换。玩家战斗行为调用 `Combat` 中的战斗形态与武器逻辑；敌人通过 `AI` 行为树判断死亡、受击、发现玩家、攻击距离等条件，再切换到对应敌人状态。

`Framework` 为其他层提供横向能力：

- `ABManager` 和 `ResMgr` 负责资源加载。
- `UIManager` 负责 UI 面板生命周期。
- `PoolMgr` 负责对象复用。
- `EventCenter` 负责跨模块消息分发。
- `SceneMgr`、`MusicMgr`、`EffectMgr` 负责场景、音频和特效。

## 关键设计点

- 管理器统一采用单例模式，降低场景切换时的重复初始化成本。
- UI、特效和部分战斗对象通过对象池复用，减少频繁 Instantiate/Destroy。
- 玩家和敌人的动作逻辑收敛到状态机，避免控制器类无限膨胀。
- 敌人决策使用行为树组合，普通敌人只需声明决策顺序即可复用底层节点。
- 战斗形态使用控制器加数据配置的结构，便于扩展普通形态、武器形态和变身形态。
