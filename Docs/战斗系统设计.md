# 战斗系统设计

## 核心目标

战斗系统围绕玩家的多形态战斗展开：普通形态、武器 A、武器 B 和变身形态都通过统一入口管理，具体行为由形态对象和武器对象承接。

## 核心类

- `CombatFormController`：战斗形态总控，负责初始化默认形态、切换形态、维护当前战斗数据、处理能量消耗和武器挂载。
- `CombatContext`：战斗上下文，向形态和武器传递玩家、数值、当前形态等共享信息。
- `ICombatForm` / `CombatFormBase`：战斗形态接口与基类，定义进入、退出、Tick、攻击等生命周期。
- `NormalCombatForm`、`WeaponACombatForm`、`WeaponBCombatForm`、`TransformCombatForm`：不同形态的具体实现。
- `WeaponCombatBase`：武器战斗公共逻辑，管理攻击段、命中、连招窗口和动画事件。

## 数据流

玩家输入触发攻击或技能后，玩家状态机会进入对应战斗状态，并调用 `CombatFormController` 的当前形态。当前形态根据 `CombatData` 选择攻击段，再把具体攻击执行交给挂载的武器逻辑。

命中敌人后，武器或攻击逻辑会驱动伤害、能量增长、特效和 UI 反馈。变身形态会持续消耗能量，能量耗尽后自动回到普通形态。

## 扩展方式

- 新增战斗形态：实现 `ICombatForm` 或继承 `CombatFormBase`，再在 `CombatFormController` 中接入配置和切换逻辑。
- 新增武器：继承 `WeaponCombatBase` 或实现 `IWeaponCombat`，复用连招和攻击窗口基础流程。
- 新增攻击数据：扩展 `CombatData` 派生配置，保持控制逻辑与数值配置分离。
